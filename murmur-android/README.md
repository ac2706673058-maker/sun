# 絮语 Murmur · Android 角色扮演客户端

原生 Kotlin + Jetpack Compose，接任意 OpenAI 兼容接口。
不是套壳网页，不是 WebView，没有账号、没有服务器、没有埋点。

**核心目标只有一个：让角色在几百轮之后还是同一个人。**

---

## 装

`dist/murmur-1.0.apk`，直接传到手机点开安装（需要允许"安装未知来源应用"）。
Android 8.0 以上，arm64 / armv7 / x86 都能跑。

第一次打开会走三步：确认年龄 → 填接口 → 进去聊。

## 配接口

设置里填三样东西：

| 填什么 | 说明 |
| --- | --- |
| 接口地址 | 填到 `/v1` 就行，会自动补 `/chat/completions`。不写 `http(s)://` 默认按 https 处理 |
| API Key | 只存在这台手机的私有目录里 |
| 模型名 | 手填，或者点「拉取模型列表」从 `/models` 拉下来选 |

内置了 OpenAI / DeepSeek / OpenRouter / 硅基流动 / Moonshot / 智谱 的地址快捷键。
填完点「测试连接」，通不过会直接告诉你是 Key 不对、地址不对、还是模型名不存在。

**客户端不做任何内容过滤**——没有关键词表，没有分类器，不改写你的输入，不拦截模型的输出。
尺度完全取决于你接的那个服务端。唯一写死的一条是提示词里的「所有出场角色均为成年人」。

## 长对话为什么会垮，以及这里怎么处理

聊到几十上百轮之后，角色开始变味，基本是三件事同时发生的：

1. **系统提示离生成位置越来越远**，注意力权重被稀释，人设指令逐渐失效；
2. **模型忘了此刻的物理状态**——刚才还在厨房，下一句突然在床上，衣服换了也不知道；
3. **助手人格回潮**——开始解释、总结、征求同意、在结尾问"你想怎么做？"。

对应三个机制：

### 深度锚点（Anchor）

不是把人设堆在开头就完事。每次生成时，在**对话末尾附近**（默认倒数第 1 条之前）再插一段紧凑的重述：
你是谁、说话什么调、现在在哪、穿着什么、什么情绪、有哪些没了结的事、哪些词最近用滥了。

越靠后的 token 权重越高，这是对抗长上下文衰减最直接的手段。插入深度可调。

### 场景状态跟踪（SceneState）

每轮结束后，后台用一次便宜的小请求把当前场景抽成结构化状态：

```json
{"location":"直播间","time":"凌晨两点四十","pose":"她瘫在椅背上，隔着桌子",
 "outfit":"宽大的针织衫","mood":"疲惫但没打算走","threads":["答应过要请她吃夜宵"]}
```

这份状态每轮进锚点。地点、姿态、穿着这些东西一旦写进去，就不会再飘。
抽取失败时沿用旧值，绝不清空。

### 分层预算装配

上下文不是"塞满为止"，而是按块分配、按优先级退让：

```
system  底线 + 主提示词 + 文体规则
system  角色卡（身份 / 性格 / 说话方式 / 情境）
system  你的人设
system  世界书（命中关键词的条目）
system  长期记忆（按与当前话题的相关性挑选）
system  前情梗概（被挤出窗口的旧对话压缩而来）
system  示例对白（语气锚）
        ……历史消息……
system  ★ 深度锚点
        ……最后 N 条消息……
system  尾部指令
```

预算吃紧时的退让顺序是 **示例对白 → 世界书 → 记忆 → 梗概**，
并且历史对话有保底占比（默认 50%），设定块再长也不会把对话本身挤没。
置顶的消息永不被裁掉，隐藏的消息永不进上下文。

### 另外两件

- **长期记忆**：每隔几轮自动抽取值得记住的事实（名字、约定、喜好、经历、身体特征），
  存成带重要度的条目。用字符二元组重叠做相关性排序，只把和当前话题有关的塞回上下文——
  不用 embedding，不联网，毫秒级。可以手动增删改，也可以固定某条永远优先。
- **归档梗概**：被挤出窗口的对话不是直接丢掉，而是攒够一批压缩成前情提要，
  明确要求保留专有名词、约定和关系转折。

这四件事都能单独关掉，也都能在「设置 → 上下文引擎」里调参数。

## 用起来

- **候选回复**：不满意就重生成，旧的留作候选，左右滑动切换，`2/3` 这样标着
- **接着写**：回复被截断了，或者写得太短，让它从断点续下去，不重开头
- **替我想一句**：不知道该说什么的时候，让模型以你的身份写一句填进输入框
- **让 TA 继续说**：不输入任何内容直接推进，沉默也是一种回应
- **从这里分叉**：对同一段剧情试不同走向，原对话不受影响
- **固定 / 隐藏**：把关键设定钉死在上下文里；把场外备注排除出上下文但保留显示
- **看看发了什么**：菜单里能看到这一轮拼给模型的完整提示词，一字不差，以及各块占了多少 token

正文排版会把 `*动作*` 压暗成斜体、对白提亮，长回复一眼能分清谁在说话、谁在动。
流式输出做了平滑：把服务端爆发式返回的分块摊匀到每一帧，看起来像真的在打字。

## 角色

内置四个人设（林晚 / 顾青梧 / 苏酥 / 艾达），语气和主动性刻意拉开距离。
它们都能直接改，改坏了可以复制一份再改。

**支持 SillyTavern / Chub 的角色卡**：PNG（数据藏在 tEXt 块里）和 JSON 都能直接导入，
连带世界书一起。也能导出成 V2 规格的 JSON 给别的客户端用。
网上现成的几万张卡拖进来就能用。

## 想用本地模型 / 无审查微调

**不需要改这个 App——它已经支持了。** 只要那个东西能开一个 OpenAI 兼容的 `/v1` 出来，
在设置里把地址指过去就行。

三条路，按体验从好到差：

**1. 家里的电脑跑，手机连过去（最推荐）**
用 llama.cpp 的 `llama-server`、Ollama、vLLM、TabbyAPI 都行，加载你选的无审查微调，
然后手机填 `http://电脑的局域网IP:端口/v1`。手机和电脑在同一个 WiFi 下即可。
出门想用就再套一层内网穿透。这条路能跑 14B~32B，上下文也开得大，体验和云端 API 没差别。

**2. 手机上直接跑**
Termux 里编译 llama.cpp 跑 `llama-server`，然后 App 连 `http://127.0.0.1:8080/v1`。
Redmi Turbo 5 Max 这个配置，8B 的 Q4_K_M 量化大概占 5GB 内存，解码速度还行。
但要注意：**长上下文的 prefill 才是瓶颈**，8k 上下文首次响应可能要几十秒。
这个 App 的上下文引擎本来就吃上下文，所以本地跑的话建议把上下文长度调到 4k~8k，
并且把「场景跟踪 / 记忆抽取 / 归档梗概」的后台任务关掉或者调稀疏一点，不然每轮要多跑好几次推理。

**3. 找无审查模型**
HuggingFace 上搜 `abliterated`、`uncensored`、`RP`、`roleplay` 这些 tag。
中文角色扮演的话，基于 Qwen 系列的微调通常比英文底座的效果好。
挑好之后下 GGUF 量化版给 llama.cpp 用。具体哪个好非常主观，建议拿同一段开场白横向试几个。

顺带一提：设置里的「后台任务模型」可以单独指定一个便宜的小模型去跑摘要和记忆抽取，
主对话用好模型。混着用能省不少钱，本地跑也能省不少时间。

## 隐私

对话、角色、记忆、API Key 全部存在应用私有目录里，没有云端，没有账号，没有分析 SDK。
唯一的出站请求就是发给你自己填的那个接口。

## 从源码构建

```bash
ANDROID_HOME=/path/to/android-sdk ./gradlew assembleRelease
```

产物在 `app/build/outputs/apk/release/`。
仓库里带了一份开发签名密钥（`murmur-release.jks`），这样每次重新构建产出的 APK 签名一致，
可以直接覆盖安装升级，不用卸载重装。要换成自己的密钥就在根目录放一个 `keystore.properties`：

```properties
storeFile=my.jks
storePassword=...
keyAlias=...
keyPassword=...
```

跑测试：

```bash
./gradlew testReleaseUnitTest
```

67 个单元测试，覆盖上下文装配（锚点位置、预算裁剪、置顶保留、世界书命中、记忆排序）、
SSE 流式解析（分片、粘包、错误体、非流式回退）、角色卡导入导出往返、以及 token 估算。

## 已知边界

- 开发环境没有 Android 真机也没有模拟器（无 KVM），所以 UI 是按 Compose 语义写的，
  逻辑层用单元测试覆盖，但**界面本身没有在真机上跑过**。有问题告诉我。
- Release 构建**没开 R8 代码压缩**。keep 规则写好了，但没法真机验证，
  不值得为了几 MB 冒一个装上去打不开的险。要开就把 `app/build.gradle.kts` 里那两个 `false` 改回 `true`。
- 没做群聊（多角色同场），没做图片生成，没做语音输入。
